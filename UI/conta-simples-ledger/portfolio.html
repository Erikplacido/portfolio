Problema de Negócio

Inconsistência que virou custo

"Na Conta Simples, o crescimento do produto de múltiplos cartões corporativos gerou inconsistências graves de interface. As equipes de mobile e web utilizavam soluções visuais divergentes para apresentar compras parceladas, transações internacionais e compras recusadas — gerando retrabalho no time de engenharia."

O desafio foi criar uma fonte única de verdade — um componente que cobrisse todos os estados e variações de dados reais, documentado para implementação sem dúvida.

Processo de Design

Estratégias de Padronização

Abordagem A

Componente Monolítico

Um único componente com muitos props para cobrir todos os casos — mais simples de manter, mas com alta complexidade interna e dificuldade de extensão.

  • API de uso mais simples para engenheiros
  • Menos componentes para documentar
  • Menor overhead de importação
Escolhida

Família Modular (TransactionRow + LedgerGroup)

Componentes focados e compostos — TransactionRow para linhas individuais e LedgerGroup para agrupamento por data — permitindo extensão sem quebrar contratos.

  • Cada componente tem uma única responsabilidade
  • LedgerGroup abstrai a lógica de agrupamento por data
  • Props bien tipados com JSON Schema facilitam handoff
  • 40+ edge cases validados com dados reais antes de congelar
Como foi Resolvido

Os 3 Pilares da Solução

Tokens Semânticos como Fundação

A definição de tokens semânticos (surface, text-primary, status-warning) ao invés de valores hard-coded permite que o mesmo componente funcione em modo claro, escuro e high-contrast sem reescrever CSS.

Design System · Tokens

Stress Test com Dados Reais

Mais de 40 edge cases de dados bancários reais foram simulados antes de congelar o componente — desde nomes de lojas com 60+ caracteres até transações internacionais com IOF e spread variável.

Validação · Edge Cases

Documentação Técnica de Handoff

Produzi documentação técnica em Markdown com exemplos de implementação em React Native e Jetpack Compose — eliminando o gargalo de alinhamento entre design e engenharia que antes consumia horas por sprint.
